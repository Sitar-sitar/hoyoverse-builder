# 修正設計書: リクエストボディ上限の縮小（2026-09-10）

[リファクタリング計画書_2026-09-08.md](リファクタリング計画書_2026-09-08.md) §4.3 #4 の回収設計。

- 対象: `server/_core/index.ts` のボディパーサ設定
- 前提コミット: `9d5cd4c`
- 種別: 修正設計書（**挙動不変ではない**。受け付けるリクエストの上限が変わる）

## 1. 背景と問題

```ts
// Configure body parser with larger size limit for file uploads
app.use(express.json({ limit: "50mb" }));
app.use(express.urlencoded({ limit: "50mb", extended: true }));
```

この 50MB はテンプレート（Manus）の既定値で、コメントの「file uploads」は本アプリには存在しない。
本アプリがボディを読む経路は次の2つだけで、いずれも数十KBに収まる。

| 経路 | 最大ボディ | 根拠 |
| --- | --- | --- |
| `POST /api/trpc/feedback.submit` | 約 12KB（最悪 32KB 弱） | `server/routers.ts` の zod スキーマ上限は `pagePath` 255 + `originalText` 800 + `suggestedText` 1000 + `notes` 2000 = 4,055 文字。UTF-8 で最大 3 バイト/コード単位、JSON エスケープ最悪 `\uXXXX` 6 バイト/コード単位 |
| `POST /api/auth/github/exchange` | 約 100 バイト | `req.body.code`（GitHub の一時コード） |

`urlencoded` を読む経路は存在しない（フォーム POST は無い）。
`/manus-storage/*`（storageProxy）は GET のみでボディを持たない。

**問題**: 未認証で叩ける `POST /api/trpc/*` に 50MB のボディを送れるため、
1リクエストで最大 50MB がプロセスのメモリへ載る。Railway の小インスタンスでは
数本の並行リクエストで容易にメモリ枯渇へ持ち込める。実害はメモリ消費に限られる
（保存はされない）が、上限を実需へ寄せない理由が無い。

## 2. 決定

### D1. 上限を **256kb** にする

計画書は「1MB 程度」と書いたが、実需の最大は 32KB 弱で、1MB には根拠が無い。
256kb は最悪ケースの約8倍で、tRPC の `httpBatchLink` が複数ミューテーションを
1本にまとめても余裕がある。express の既定（100kb）より上に置くのは、
バッチ + 多バイト文字で既定に触れる可能性を排除するため。

`json` / `urlencoded` の両方へ同じ値を入れる（`urlencoded` は現在未使用だが、
将来使われたときに 50MB へ戻らないよう明示する）。

### D2. 超過時は `/api` 配下だけ JSON で 413 を返す

`express.json` の上限超過は `PayloadTooLargeError` を投げ、既定のエラーハンドラは
HTML を返す。クライアントの tRPC リンクは JSON を期待するため、
パースエラーになって原因が分からなくなる。`/api` で始まるパスに限り

```json
{ "error": "payload_too_large", "limit": "256kb" }
```

を 413 で返すエラーハンドラを1つ足す。それ以外のパス・それ以外の例外は
`next(err)` でそのまま流す（挙動を増やさない）。

### D3. 設定を `server/_core/bodyLimits.ts` へ切り出す

`server/_core/index.ts` は末尾で `startServer()` を実行するため、テストから import できない。
上限値と `app.use` の並びを `applyBodyParsers(app)` として別モジュールへ出し、
実際に express を起動して 413 / 200 を確認する回帰テストを置けるようにする。

## 4. 受入条件

1. 32KB の JSON ボディ（最悪ケースのフィードバック相当）が 200 で通る。
2. 512KB の JSON ボディが **413** かつ `Content-Type: application/json` で返る。
3. `/api` 以外の 413 は JSON 化しない（既定のまま）。
4. `pnpm check` / 全テスト / `build:api` / Pages ビルドが green。
5. ゴールデン比較が全セクション一致（baseline 更新なし）。
6. ローカル API（`API_ONLY=true`）で `/api/health` が 200、
   `POST /api/trpc/feedback.submit` に 512KB を投げて 413 を実測する。
