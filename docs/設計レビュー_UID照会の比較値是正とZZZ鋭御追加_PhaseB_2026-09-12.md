## PB-01: HP・防御力の装備提案が同じ IV へ衝突する（P2）

**対象**: 設計書245〜253行、336〜337行、442〜444行、483行。

現行の `equipmentActionsFor` は、個別ガイドの `mainStats` に対象ラベルを含む部位がなければ `defaultSlotsForStat(...)[0]` の1部位だけを採用する（[buildAdvisor.ts](../server/buildAdvisor.ts) 153〜160行）。D4 の戻り値は `["IV", "V", "VI"]` なので、該当部位がない HP・防御力系の提案はすべて IV を選ぶ。D7 により表示文字列は有効な `HP%` / `防御力%` になるが、選択根拠と競合は解消されない。

シーザーの個別ガイドは IV を会心、V を物理属性ダメージ／貫通率、VI を衝撃力としている一方、`hp` と `defense` の両方を目標に持つ（[gameProviders.ts](../server/gameProviders.ts) 605行）。両方が不足すると、設計どおりの実装は同じ IV に「HP%へ変更」と「防御力%へ変更」を同時に返し、どちらも個別ガイドの IV 推奨と矛盾する。セスと蒼角も HP 目標を持つが、IV〜VI は攻撃力・異常掌握・エネルギー自動回復を推奨している（同593行・595行）。設計が影響確認を求める潘引壺も、HP%目標に対して全3部位を攻撃力系としている（[individualGuides.ts](../server/individualGuides.ts) 589行）。

§8 のテストは部位が IV / V / VI のどれかで、希望値が割合表記なら合格するため、同一部位への相反提案と個別ガイドとの衝突を検出できない。§5 の「個別ガイド優先」という原則も、対象ラベルがない場合には働かない。

**修正方向**: 個別ガイドに対象主ステータスがない場合の扱いを決める。候補は、主ステータス変更を出さずサブステータス厳選へ落とす、出典で裏付けたキャラクター別の代替部位を持つ、または同時に不足した複数目標を優先度と部位制約で競合解決する、のいずれかである。単に `["IV", "V", "VI"]` の先頭を選ぶ仕様にはしない。

**再レビュー・検証条件**: シーザーで `hp` と `defense` が同時に不足しても、同じ IV へ相反する変更を2件返さず、IV会心・V物理／貫通・VI衝撃力という個別ガイドと整合する。セス、蒼角、潘引壺についても、主要目標を壊す主ステータス変更を提案しない。ベンのように個別ガイドに防御力%部位がある場合は、その部位を優先する。

## PB-02: `ZZZ_PROFILES.def` の必須内容が確定していない（P2）

**対象**: 設計書227〜236行、327〜340行、441行、445行。

`ZZZ_PROFILES` の1プロファイルには `relicSet`、`planarSet`、IV〜VI の `mainStats`、`targets` が必要である（[individualGuides.ts](../server/individualGuides.ts) 35〜42行）。D2 は `targets: []` と目標を置かない理由を確定しているが、残る表示項目を「メインステータスは防御力系」としか定めていない。§4.2 の疑似コードにも `ZZZ_PROFILES.def` のオブジェクトがなく、Phase B テストは `profileId`、空目標、`targetContext` だけを確認する。

Phase B 単独公開期間や将来の個別ガイド未登録 Armorer では、この共通プロファイルが最終応答として表示される。実装者が IV〜VI のどこへ防御力%を置くか、会心・属性ダメージ・エネルギー回復などを併記するか、セット説明を何にするかを任意に決めても、現在の設計テストを通過できる。これでは D2 のユーザー向け契約と「既存6特性は不変」の回帰範囲を一意に実装できない。

**修正方向**: `ZZZ_PROFILES.def` の完全なオブジェクト、または各必須フィールドの確定値を §4.2 に記載する。数値目標は空のままとし、根拠未確認の装備名を推測しない。汎用表現を使う場合も、IV / V / VI の値と表示文を固定する。

**再レビュー・検証条件**: 未登録 Armorer の正規化結果について、`profileId: "def"`、`targets: []`、目標を置かない説明に加え、セット説明と IV〜VI の `mainStats` が設計値と一致することを確認する。既存6プロファイルの全フィールドが不変であることも比較する。

## PB-03: D7 のキー網羅と変異検出が不足する（P3）

**対象**: 設計書245〜251行、443〜446行。

D7 は ZZZ の `hp` / `hpPercent` を `HP%`、`defense` / `defPercent` を `防御力%` に変換する4キーの契約である。しかし、テスト項目3は `hpPercent` と `defense` だけを指定し、`hp` と `defPercent` の誤実装を検出しない。変異チェックも「D1〜D4・D6」となっており、D7 が列挙から漏れている。

**修正方向**: 4キーを表形式のパラメータテストで固定し、原神・HSR の同じ4キーが従来表記と部位を保つことも確認する。変異チェックを D1〜D4・D6・D7 に改める。PB-01 の競合解決後は、表示文字列だけでなく最終 `equipmentActions` の action・slot・desiredStat を検証する。
