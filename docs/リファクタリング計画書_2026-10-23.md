## 1. 現状理解（実行者への文脈共有）

### 1.1 アプリの概要

崩壊：スターレイル・原神・ゼンレスゾーンゼロのビルド支援サイト。

1. フロントエンド（React + Vite）は `vite.pages.config.ts` でビルドし、GitHub Pages（`https://sitar-sitar.github.io/hoyoverse-builder/app/`）で公開する。
2. API（Express + tRPC）は `pnpm build:api`（esbuild で `dist/index.js`）を `Dockerfile.northflank` で Northflank に配備する。本番は `API_ONLY=true`、`NODE_ENV=production`。DB は Northflank MySQL。
3. main へのマージで Northflank API が自動配備され、`.github/workflows/deploy-pages.yml` が API の revision（`APP_REVISION`）がマージ SHA と一致するのを待ってから Pages を公開する。PR は `.github/workflows/validate-api.yml` で検証する。**main へのマージがそのまま本番配備になる。**
4. 管理者ログインは GitHub App（`server/_core/githubAdminAuth.ts`）。プロジェクトは Manus のテンプレートから作られており、Manus 独自の OAuth・ストレージ・通知・開発用プラグインのコードが、本番では読み込まれないまま残っている。
5. 2026-10-08 に Railway から Northflank へ移行した。旧 Railway 用のコード（IP 判定の railway モード、health の `RAILWAY_GIT_COMMIT_SHA` 予備参照）と `railway.toml` が「旧環境互換コード」として残っている。
6. `API_ONLY` を付けずに起動するとフルスタック（開発用）モードになり、`server/_core/vite.ts` が `vite.config.ts` で Vite を組み込む。このモードは本番では使わない。

### 5.3 本番配備前ゲート G-1（マージ前・必須）

目的: 本番 API の環境変数に `CLIENT_IP_SOURCE=railway` が残っていると、R6 のコードを含む API は起動時に `Invalid CLIENT_IP_SOURCE` で停止する。マージ前にそれが無いことを確かめる。

1. **ユーザーが** Northflank のコンソールで、本番 API サービス（`hoyoverse-api`）の Environment と、そのサービスに紐づく Secret Group の全てを開き、`CLIENT_IP_SOURCE` の値を確認する。作業者（AI）は Northflank CLI/API で環境変数一覧を取得しない（秘密値を含み得るため。[設定台帳](運用管理台帳_Northflank設定_2026-10-05.md) 2026-10-05 の記録どおり、この取得は以前にも拒否している）。ユーザーから受け取るのは `CLIENT_IP_SOURCE` の値だけとし、他の変数の値を尋ねない。
2. 判定:
   - 値が `northflank` → G-1 合格。
   - 値が `railway` → マージしない。設定台帳の記録（`northflank`）と食い違っていることをユーザーへ報告し、値の変更はユーザーの判断に委ねる（作業者は Northflank の設定を変更しない）。ユーザーが値を変えた場合は、変更後の API の health が正常であることを確認してから、改めて G-1 を最初から実施する。
   - 変数が無い（未設定）→ 現行の動作は `auto` で、`RAILWAY_PROJECT_ID` も無ければ現在と同じく socket address を使うため起動は止まらない。ただし [設定台帳](運用管理台帳_Northflank設定_2026-10-05.md) の記録（`northflank`）と食い違うので、マージせずにユーザーへ報告する。
   - Migration Job は `drizzle-kit migrate` だけを実行し `validateClientIpConfiguration` を通らないため、Job の環境変数は G-1 の対象外。
3. 作業者が、本番 API の `revision` が 40 桁の SHA であること（= `APP_REVISION` で供給されていて、`RAILWAY_GIT_COMMIT_SHA` の予備参照を消しても値が変わらないこと）を確認する:

```powershell
$h = Invoke-RestMethod -Uri "https://http--hoyoverse-api--s48krvgv8tjs.code.run/api/health"
"revision=$($h.revision) ok=$($h.ok)"
if ($h.revision -notmatch '^[0-9a-f]{40}$') { throw "revision is not a 40-char SHA" }
```

4. G-1 の結果（`CLIENT_IP_SOURCE` の値、確認日時、revision）を実装ログへ記録してから、マージする。
